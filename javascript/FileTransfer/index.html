FileTransfer

Realiza transferências de arquivos entre utilizador e o servidor.

Utiliza recuros das API's XMLHttpRequest e FormData

Apresentação

NOTA:

O teste a seguir requer interpretador de linguagem PHP para funcionar.

Para informações adicionais dos processos veja o console do navegador.

Opções

url

  • download ⇒ (Obrigatório) Deve ser informado o local/arquivo onde está o arquivo para receber.
  • upload ⇒ (Obrigatório) Deve ser informado o local/arquivo para onde deve ser enviado o(s) arquivo(s).

file

  • download ⇒ (Opcional) Informe o nome para o arquivo ao final da transferência, caso não informado o nome será uma texto numério de acordo com a data e hora do utilizador.
  • upload ⇒ (Obrigatório) Deve ser informado o elemento input do tipo file ao qual os arquivos podem ser anexos.

Opções (Métodos/Callback's)

Todos métodos a seguir são opcionais, use se achar necessário

onStart

Deve informado uma função que será executada quando o script iniciar e antes da transferência começar a ser executada.

Você poderá adicionar um parâmetro de retorno, exemplo:

onStart: function (param) {}

Este parametro é nulo quando o processo usado for download sendo assim desnecessário, ou seja inútil para quaisquer usos.

Entretanto quando o processo for upload o parâmetro irá retornar um objeto com os dados do arquivo selecionado no elemento[input].

onStart: function (retorno) {
    console.log(retorno);
    /* Assim retornando um objeto com as seguintes informações:
    {
        name: 'Nome do arquivo selecionado',
        size: 'Tamanho do arquivo selecionado',
        type: 'MimeType do arquivo selecionado'
    }
    */
}

Em condição quando o elemento[input] tenha o atributo multiple significa que ele aceita vários arquivos.

Nesse caso o retorno será um objeto multiplo com todos os dados listados acima de acordo com cada arquivo selecionado.

Considere usar como preparação e validação, onde qualquer requisito não esteja como esperado pode ser validado durante essa etapa.

Essa função pode negar o acionamento de todos os demais processos caso a mesma retorne falso, assim parando a execução impedindo todo resto de prosseguir.

Exemplo:

onStart: function (param) {
    if (condicional !== 'requisito') {
        return (false);  // O FileTransfer só executará esse método e vai parar aqui devido ao retorno falso
    }
}

onProgress

Deve ser informado uma função que será executada repetitivamente até que o processo de transferência termine ou seja interrompida por algum motivo.

Sim! Essa função vai ficar se repetindo, portanto cuidado.

Você também poderá adicionar um parâmetro ao qual retorna a porcentagem do progresso executado.

Exemplo:

onProgress: function (percentual) {
    console.log(percentual); // (%) porcentagem completado da tranferência
}

onError

Deve ser informado uma função que será executada caso aconteça algum erro na transferência.

Você também poderá adicionar um parâmetro ao qual normalmente retorna a o código http de estado.

Para detalhes sobre o identificação do código http leia esse artigo.

Exemplo:

onError: function (err) {
    console.log(err);
}

onCancel

Deve ser informado uma função que será executada caso a transferência seja abortada.

Veremos mais adiante o método extra para essa finalidade.

Exemplo:

onCancel: function () {
    // O que fazer quando for abortada a tranferência
}

onResult

Deve ser informado uma função que será executada quando a transferência for concluída com sucesso.

Somente quando for utilizado o recurso de upload pode-se adicionar um parâmentro que retorna a resposta do servidor medianteos arquivos recebidos, isso se o servidor dizer algo como resposta.

Exemplo:

onResult: function (resposta) {
    console.log(resposta); // Resposta do servidor quando recebeu/manipulou o(s) arquivo(s)
}
<?php
var_dump($_FILES); // Resposta do servidor PHP

Considere usar essa função para finalizar qualquer adicional que esteja ainda em funcionamento dentros das funções onStart e onProgress

NOTA:

Seja no recuso upload ou no download, o recebimento ou a resposta do servidor só estará disponível um segundo depois de terminado.

Ou seja mesmo completado a tranferência o arquivo só é enviado no download ou a resposta no upload são acionados apenas um segundo após a conclusão.

Método Extra

Para parar a transferência, basta utilizar a função cancel(), pode ser ativada a qualquer momento para abortar a operação, mas seu funcionamento só é ativo enquanto houver alguma transferência em andameto, caso contrário nada acontecerá.

Exemplo:

<button id="parar">Abortar Transferência</button>
<script>
    const transferir = new FileTransfer();
    document.getElementById('parar').addEventListener('click', function () {
        transferir.cancel();
    }, false);

    transferir.download({
        url: 'https://local/arquivo.tipo',
        onCancel: function () {
            console.log('Transfernecia de arquivo cancelada');
        }
    });
</script>

Restrições do Servidor

Tanto um download quanto um upload normalmente um servidor irá impedir o acesso ou aquisição de arquivos.

Em certos casos conforme for a extensão do arquivo até a quantidade de dados desses arquivo não poderá ser efetuado o download.

No caso de upload/download o destino final também estiver bloqueado de acesso resultará em erro 404.

Na maioria das vezes um servidor já está configurado para limitar qual o limite máximo de dados que ele pode receber.

Você sempre poderá está modificando esses acessos ou configurações conforme desejar.

Vejamos o caso de um servidor onde sua linguagem é o PHP, bastando apenas alterar o PHP.INI

  • post_max_size ⇒ limita o tamanho máximo de caracteres (também meta-dados) que que ele aceitará.
  • upload_max_filesize ⇒ limita o tamanho máximo que o servidor aceitará quando um arquivo for enviado para ele.

Boas Práticas e questão de legislação

NUNCA! JAMAIS! DE FORMA ALGUMA!

Você não pode enviar ou requisitar arquivos de um usuário sem que ele realmente saiba que está prestes a fazer um download ou upload iminente, ambas ações devem ficar bem claras antes de serem inicidas.
